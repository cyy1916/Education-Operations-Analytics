# 教育运营数据管理与分析项目

# 03 数据资产盘点

> Data Inventory & Data Audit

---

## 1. 文档目的

本文件在《01 项目章程》和《02 当前状态分析》的基础上，对当前在线语言教育业务中已经存在的数据资产进行系统盘点。

前两份文件已经分别回答：

* 《01 项目章程》：项目为什么启动、核心痛点是什么、项目准备如何推进；
* 《02 当前状态分析》：市场、销售、教务和课程交付当前实际如何运行，以及 P1–P5 核心痛点具体出现在哪些流程。

本阶段进一步回答：

> 当前到底有哪些数据可以使用？

以及：

> 这些现有数据能否支持前述业务问题的分析和后续数据建模？

因此，本阶段的重点不是立即设计数据库，而是先确认现有数据资产的：

* 来源；
* 所属业务流程；
* 维护方式；
* 业务粒度；
* 主要字段；
* 时间范围；
* 更新方式；
* 关联方式；
* 数据质量问题；
* 对 P1–P5 的支持程度；
* 为后续分析仍然缺少哪些关键字段。

## 2. 数据盘点范围

目前业务运营主要依赖 Excel / Google Sheets 管理不同业务环节的信息，包括：

* 市场获客；
* 客户咨询；
* 销售跟进；
* 试听与等级测试；
* 正式报名；
* 学生管理；
* 私教课程；
* 班课；
* 课程安排；
* 课程执行；
* 教学反馈；
* 异常处理；
* 续费与学生状态；
* 运营统计。

本阶段既盘点当前已经明确识别的数据源，也记录当前数据资产中仍然存在的缺口。

需要特别区分：

```text
现有数据
≠
后续分析需要的数据
```

某个字段在后续分析中非常重要，并不代表当前历史文件中已经稳定存在。

因此，本文件将“已经存在的数据”和“后续需要补充或重新建模的数据”分开描述。

# 3. 当前数据规模概览

## 3.1 班课数据

近两年线上和线下 A1、A2、B1、B2 班课均按照等级和授课形式分别建立独立表格。

目前估算：

* 线上班课每个等级约有 80–100 份独立表格；
* 线下班课每个等级约有 20–40 份独立表格。

按照四个主要等级估算：

```text
线上班课：
4 × 80–100 ≈ 320–400 份

线下班课：
4 × 20–40 ≈ 80–160 份
```

仅班课相关文件约为：

```text
400–560 份
```

上述估算尚未包含全部：

* 课程安排表；
* 汇总表；
* 教师相关辅助表；
* 历史归档文件；
* 临时运营表。

---

## 3.2 私教数据

近四年私教课程中：

* 当前仍在管理或保留记录的私教课程超过 150 组；
* 已停课私教课程约 30–40 组。

因此，仅目前可以确认的私教历史课程组规模已经超过约 180 组。

私教又包括：

* 一对一；
* 一对二；
* 一对三；
* 一对四。

不同私教课程组的学生、教师、时间和课程状态均可能持续发生变化。

---

## 3.3 课程安排数据

课程安排表目前仍然按照：

```text
课程等级
+
线上 / 线下
↓
不同课程安排表
```

分别管理。

这意味着课程安排本身并不存在一个天然统一的数据源。

---

## 3.4 数据规模对本项目的意义

当前面对的并不是一份能够直接导入分析工具的数据集，而是：

```text
多年历史文件
+
数百份班课文件
+
大量私教课程组
+
不同部门业务表
+
课程安排表
+
运营辅助表
+
历史归档
```

因此，数据资产盘点不仅需要记录“有哪些字段”，还必须首先回答：

> 哪些文件描述的是同一种业务对象？

以及：

> 哪些文件可以被统一处理，哪些文件因为结构和业务规则不同必须分开处理？

这直接对应项目章程中的：

> **P1 数据分散导致业务对象无法稳定贯通。**

# 5. 数据来源详细盘点

## 5.1 市场数据

### 5.1.1 小红书客户咨询表

#### 数据用途

用于记录小红书广告投放和内容运营产生的客户咨询信息。

客户点击广告或通过内容产生互动后进入咨询流程，相关信息按照日期记录。

#### 更新方式

* 以天为单位记录；
* 原则上不修改历史咨询记录；
* 如果客户再次咨询或产生新的操作，则新增记录。

这一更新方式意味着：

> 当前记录的业务粒度更加接近“一次客户互动 / 咨询事件”，而不是“一个唯一客户”。

#### 主要数据内容

| 分类 | 当前字段 |
| --- | --- |
| 客户信息 | 编号、日期、客户编号、客户账号 |
| 咨询来源 | 咨询类型、广告帖子编号、引流账号 / 私信账号 |
| 销售跟进 | 负责人、销售名片、微信添加状态 |
| 时间信息 | 咨询时间、回复时间、响应时间 |
| 客户需求 | 关键词（零基础、小孩课程、B2 等） |
| 客户地区 | 网络地址地区、国内 / 海外信息 |
| 行为数据 | 点击次数 |

#### 业务分析用途

当前数据可以用于：

* 广告带来的咨询数量；
* 客户来源；
* 销售响应效率；
* 客户添加微信后的转化情况。

#### 当前主要问题

同一个客户可能产生多条记录，因此不能直接将：

```text
咨询记录数量
=
唯一客户数量
```

当前数据需要进一步区分：

```text
Customer
和
Interaction
```

否则会影响：

* 唯一客户数；
* 重复咨询率；
* 客户来源归因；
* 销售漏斗；
* 后续试听和报名关联。

对应：

> **P2 业务对象与数据结构不匹配。**

---

### 5.1.2 小红书运营帖子表

#### 数据用途

用于记录不同运营账号发布内容的数据表现。

#### 更新方式

* 按月统计；
* 以运营账号为单位维护。

#### 主要数据内容

| 分类 | 当前字段 |
| --- | --- |
| 帖子信息 | 帖子编号、作品名称、发布时间 |
| 运营信息 | 运营人员名称 |
| 数据表现 | 曝光量、账号总曝光量、账号总粉丝量 |

#### 业务分析用途

用于分析：

* 不同账号的内容表现；
* 帖子曝光效果；
* 内容运营增长情况。

#### 当前主要问题

当前数据同时涉及：

* 账号层级；
* 帖子层级；
* 月度汇总层级。

如果直接在同一粒度进行统计，容易造成：

* 账号汇总指标被重复累计；
* 帖子和账号表现混合；
* 无法稳定连接到客户咨询。

后续数据模型需要至少区分：

```text
运营账号
↓
帖子
↓
客户咨询事件
```

# 5.2 销售数据

## 5.2.1 试听课对接表

### 数据用途

用于管理试听课程安排以及试听流程。

### 主要数据内容

| 分类 | 当前字段 |
| --- | --- |
| 学生信息 | 学生姓名 |
| 销售信息 | 商业课程顾问 |
| 试听信息 | 试听班级、试听形式 |
| 学生情况 | 学生背景、学习目标、备注 |
| 教务安排 | 时间安排、教师安排、教学组确认 |

### 业务分析用途

用于分析：

* 试听数量；
* 试听完成情况；
* 试听转化率；
* 不同教师的试听情况。

### 当前主要问题

试听表同时承担：

* 客户 / 学生信息；
* 试听事件；
* 销售负责人；
* 教师安排；
* 教务确认；

等多种信息。

因此需要进一步区分：

```text
客户 / 学生主体
+
试听事件
+
教师安排
+
教务确认
```

特别是“时间安排”“教师安排”“教学组确认”字段，对后续分析 P4 跨部门信息失真问题非常关键。

需要在下一阶段确认：

* 是否可以恢复销售最初提供给客户的时间；
* 是否可以恢复教务确认时间；
* 是否能够区分客户偏好、销售承诺和最终排课。

当前数据资产盘点不能假设这些历史信息一定完整存在。

## 5.2.2 等级测试表

### 数据用途

用于记录学生语言水平测试和课程匹配信息。

### 主要数据内容

| 分类 | 当前字段 |
| --- | --- |
| 学生信息 | 学生姓名 |
| 销售信息 | 商业课程顾问 |
| 测试信息 | 测试形式（线上 / 线下） |
| 学生情况 | 当前水平、学习目标、背景信息 |
| 教务安排 | 测试时间、课程建议、教学组确认 |

### 业务分析用途

用于：

* 学生水平分析；
* 课程推荐；
* 后续报名跟踪。

### 当前主要问题

* 是否需要区分试听与纯等级测试；
* 同一个学生是否可能多次测试；
* 测试结果是否会被后续覆盖。

# 5.3 学生与教务运营数据

## 5.3.1 学生汇总表（已报名学生）

### 数据用途

用于管理已经完成报名的学生信息。

### 主要数据内容

| 分类 | 当前字段 |
| --- | --- |
| 学生信息 | 学生姓名、国家、年龄 |
| 课程信息 | 上课形式（一对一、一对二、一对三、一对四、班课等） |
| 人员关系 | 销售负责人、教师、教务负责人 |
| 学生特点 | 学生及家长性格特点 |
| 课程管理 | 课程记录链接、下月课程更新状态 |
| 续费管理 | 是否需要续费 |

### 当前主要问题

该表既包含相对稳定的学生属性，也包含持续变化的运营状态。

例如：

```text
学生姓名 / 国家 / 年龄
```

更接近 Student 主体信息。

而：

```text
教师
课程形式
下月课程更新状态
是否需要续费
```

属于学生在某一时期的课程和运营关系。

因此：

> Student 主体与 Enrollment / Course / Operational Status 存在混合。

这对应：

> **P2 业务对象与数据结构不匹配。**

---

## 5.3.2 已停课 / 已完成学生表

### 数据用途

用于管理已经结束课程或暂停学习的学生。

### 主要数据内容

与学生汇总表基本保持一致，包括：

* 学生基本信息；
* 课程形式；
* 教师；
* 教务负责人；
* 课程记录；
* 续费情况。

### 业务分析用途

用于：

* 学生生命周期管理；
* 学生流失分析；
* 学生续费分析。

### 当前主要问题

“在读学生”和“已停课 / 已完成学生”使用不同表格保存，本质上是通过：

```text
学生所在文件
```

表达学生状态。

这会导致：

* 状态变化时间未必明确；
* 学生从在读移动到停课表时，原状态过程可能丢失；
* 暂停后恢复等复杂生命周期难以表达；
* 同一学生可能在多个表中留下重复记录。

因此，后续需要将：

```text
Student
```

和：

```text
Student Status History
```

分开设计。

对应：

> **P3 状态覆盖导致历史过程丢失。**

---

## 5.3.3 学生课程记录表

### 数据用途

用于记录每个月学生具体课程的执行情况。

### 更新方式

按月份进行记录。

### 主要数据内容

| 分类 | 当前字段 |
| --- | --- |
| 学生信息 | 学生姓名 |
| 课程信息 | 课程类型、教师、课程序号 |
| 时间信息 | 上课日期、中文星期、西班牙语星期、英语星期 |
| 时区信息 | 西班牙时间、学生当地时间、时差 |
| 课时管理 | 课时计算 |
| 教学反馈 | 当日学习内容、页数、教师反馈 |

### 业务分析用途

用于：

* 课程完成情况统计；
* 教师工作量分析；
* 学生学习进度分析。

### 当前主要问题

课程记录能够描述“实际发生的一次课程”，但需要进一步确认是否能够稳定关联到：

* 具体报名；
* 私教课程组；
* 班级；
* 原计划排课；
* 调课记录；
* 学生出勤状态。

如果这些关系不存在，则后续虽然能够统计授课数量，却难以分析：

> 原计划和实际执行之间发生了什么变化。

# 5.4 班课、私教与课程安排数据

## 5.4.1 班课文件

当前近两年 A1、A2、B1、B2 班课按照线上 / 线下分别维护。

估算共有约 400–560 份独立文件。

班课文件通常围绕：

* 班级；
* 教师；
* 学生；
* 课程时间；
* 课程记录；

进行管理。

### 当前主要问题

一个新班级通常意味着增加新的独立文件。

因此业务扩展方式接近：

```text
新增班级
↓
新增表格
```

而不是：

```text
新增班级记录
↓
写入同一结构
```

这会持续扩大 P1 数据分散问题。

---

## 5.4.2 私教课程文件

近四年当前可确认：

* 在管 / 有记录私教超过 150 组；
* 停课私教约 30–40 组。

私教排课高度依赖：

* 学生时间；
* 教师时间；
* 多人私教中其他学生时间。

### 当前主要问题

如果私教调整直接更新当前课程时间，则无法稳定保留：

* 原课程时间；
* 调整日期；
* 调整原因；
* 谁提出调整；
* 调整次数；
* 对其他学生或教师产生的影响。

因此私教数据是 P3 历史追踪和 P5 人工协调问题的重要数据来源。

---

## 5.4.3 课程安排表

课程安排表继续按照等级和线上 / 线下拆分。

当前需要进一步盘点：

* 是否存在统一教师编号；
* 是否存在统一课程编号；
* 是否可以识别教师当前已占用时间；
* 是否保留教师可用时间；
* 是否保留历史课程调整；
* 是否能够区分暂定时间和最终确认时间。

这些字段将直接决定后续是否能够分析：

> 销售承诺、教师真实资源和最终排课之间的差异。

---

# 5.5 运营管理数据

## 5.5.1 异常事件记录表

### 数据用途

用于记录日常运营过程中发生的问题以及对应处理情况。

### 主要数据内容

| 分类 | 当前字段 |
| --- | --- |
| 时间信息 | 日期、星期 |
| 事件信息 | 工作类别、具体事项 |
| 关联对象 | 学生、班级、教师 |
| 负责人 | 记录人、负责人 |
| 优先级 | 优先级 |
| 状态管理 | 状态、截止时间、完成时间 |
| 异常管理 | 是否异常、异常等级 |
| 处理记录 | 处理结果、后续跟进、备注 |

### 业务分析用途

用于：

* 运营问题统计；
* 教学质量管理；
* 异常处理效率分析。

### 当前分析价值

这一数据源可能成为分析 P4 / P5 的重要依据。

例如，如果异常事件中能够稳定识别：

* 排课冲突；
* 教师临时调整；
* 客户时间承诺问题；
* 信息传递错误；

则可以用于量化：

> 教务协调和操作错误是否在某一时期明显增加。

但需要先检查异常类型是否已经标准化。

---

## 5.5.2 教务团队奖金评分数据

### 数据用途

用于记录教务团队的月度表现评价。

### 主要数据内容

包括：

* 教学运营稳定性；
* 班级健康度；
* 学员满意度；
* 教学材料完成情况；
* 教师协作情况。

### 业务分析用途

用于：

* 团队绩效评价；
* 教学质量分析。

### 当前限制

该数据属于汇总评价数据。

它可以用于观察整体变化，但不能替代：

* 单个排课事件；
* 单个异常；
* 单次教师调整；
* 单个学生状态变化；

等明细数据。

# 5.6 月度汇总统计

* 学生总数；

# 6. 当前数据关系

根据现有业务流程，不同数据之间理论上存在：

```text
小红书广告 / 帖子
        ↓
客户咨询
        ↓
试听 / 等级测试
        ↓
报名学生
        ↓
课程 / 排课
        ↓
课程记录
        ↓
续费 / 停课 / 完成
```

但目前这些关系主要通过人工字段进行关联，例如：

* 学生姓名；
* 客户账号；
* 微信信息；
* 课程记录链接；
* 文件位置；
* 人工经验。

这意味着：

> 业务流程存在关系，但数据中未必存在稳定的关系键。

因此，后续不能直接假设所有文件都可以通过 JOIN 自动连接。

# 8. 重点业务案例的数据可用性检查

项目章程和当前状态分析中已经识别出一个需要重点验证的业务案例：

```text
销售与教务信息确认机制脱节
↓
前端承诺教师时间
↓
后端重新协调
↓
短期转化提升
↓
后续运营压力增加
↓
约两个月后转化下降
+
同期教师离职率上升
```

当前已有数据可能支持：

### 已有或较可能恢复

* 试听数量；
* 报名 / 转化结果；
* 销售负责人；
* 试听教师；
* 教务安排；
* 部分异常事件；
* 月度转化率；
* 课程记录。

### 当前数据盘点中尚未确认稳定存在

* 销售最初向客户承诺的教师时间；
* 客户最初时间偏好；
* 教务实际确认时间；
* 教师真实可用时间历史；
* 每一次重新排课时间；
* 每次改课原因；
* 教务处理耗时；
* 教师正式停止授课 / 离职日期；
* 教师离职原因。

因此，后续不能提前承诺一定能够完成严格因果分析。

更现实的分析路线是：

1. 先确认哪些历史字段可以恢复；
2. 计算业务变化前后的转化趋势；
3. 统计同期排课、异常和教师变化；
4. 检查时间关联；
5. 对无法观察的变量明确标记数据限制。

# 9. 初步数据审计发现

## 9.1 数据分散

### 发现

不同业务环节分别使用不同表格维护数据。

例如，一个学生的信息可能分布在：

* 试听表；
* 测试表；
* 学生汇总表；
* 班课 / 私教表；
* 课程安排表；
* 课程记录表；
* 已停课 / 已完成学生表。

### 影响

可能导致：

* 查询历史信息需要人工整理；
* 跨部门分析成本高；
* 学生完整业务过程难以快速追踪。

对应：

> P1 数据分散。

---

## 9.2 数据重复维护

### 发现

部分信息需要在多个文件中重复填写。

例如：

* 学生姓名；
* 教师；
* 课程类型；
* 学习状态；
* 销售负责人；
* 教务负责人。

### 影响

可能导致：

* 信息更新不同步；
* 不同文件出现不同版本；
* 后续统计需要人工核对。

---

## 9.3 数据标准缺失

### 发现

部分业务分类没有统一的数据标准。

例如，同一种课程形式可能出现：

* 一对一；
* 私教；
* 单人私教。

### 影响

可能影响：

* 数据统计；
* 查询与分析；
* KPI 计算；
* 不同文件之间的数据整合。

---

## 9.4 数据粒度混合

当前数据中存在：

* 账号；
* 帖子；
* 客户互动；
* 客户；
* 学生；
* 报名；
* 课程组；
* 单次课程；
* 当前运营任务；

等不同粒度。

如果不先确定：

> 一行数据到底代表什么？

后续数据合并容易产生重复统计。

---

## 9.5 关联键不足

当前关系大量依赖：

* 姓名；
* 微信；
* 平台账号；
* 文件链接；
* 人工判断。

后续需要建立稳定 ID，但这些 ID 属于：

> **后续标准化和建模结果**

而不是应该被误写为所有历史源文件已经存在的字段。

---

## 9.6 历史状态不足

当前部分数据能够看到：

* 当前学生状态；
* 当前课程时间；
* 当前教师；
* 当前续费需求。

但不一定能够恢复：

* 状态何时变化；
* 原状态；
* 调整次数；
* 原教师；
* 原排课。

这限制：

* 学生生命周期分析；
* 排课质量分析；
* 运营政策影响分析。

---

## 9.7 缺少部分分析字段

### 学生留存与续费

目前可能缺少或尚未确认稳定存在：

* 续费时间；
* 流失时间；
* 流失原因；
* 续费次数。

### 市场分析

目前可能缺少：

* 广告成本；
* 不同渠道投入金额；
* 客户最终来源归因；
* 单个客户获客成本。

### 排课与跨部门分析

目前尚未确认稳定存在：

* 客户偏好时间；
* 销售承诺时间；
* 教师可用时间历史；
* 教务确认时间；
* 排课调整时间；
* 调整原因；
* 调整发起人。

### 教师稳定性

目前尚未确认稳定存在：

* 教师入职 / 开始授课日期；
* 教师离职 / 停止授课日期；
* 离职原因；
* 不同时期教师负荷快照。

这些字段的缺失会限制后续分析能力。

# 10. 数据盘点阶段结论

通过本阶段的数据资产盘点，可以初步确认：

当前业务已经积累了覆盖市场、销售、教务、课程执行和运营管理等多个环节的数据。

现有数据并非无法用于分析。

真正的问题是：

```text
数据已经存在
↓
但分散在不同文件
↓
粒度和定义不统一
↓
业务对象关系不稳定
↓
部分历史状态被覆盖
↓
关键跨部门确认信息未被系统记录
↓
分析前需要重新结构化
```
