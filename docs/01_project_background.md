# 教育运营数据管理与分析项目

# 01 项目背景

# 1. 项目概述

本项目是一个基于个人工作经历和实际业务场景构建的**数据分析作品集项目**。

项目来源于在线语言教育机构日常运营过程中，对市场获客、销售转化、学生管理、课程执行以及运营统计流程的观察。

随着学生数量、教师数量以及课程规模不断增加，业务逐渐依赖电子表格完成信息记录、流程管理以及数据统计。

当前电子表格体系主要承担：

* 数据存储；
* 信息查询；
* 状态跟踪；
* 问题记录；
* 运营统计；
* 月度汇报。

在业务规模较小时，电子表格具有灵活、成本较低、易于维护等优势，可以快速支持日常运营。

但是，随着业务流程不断增加，业务数据、流程管理和分析需求逐渐集中在同一套文件体系中，使数据维护、跨部门协作以及业务分析变得更加复杂。

因此，本项目希望通过梳理当前业务流程、数据来源以及数据结构，分析现有数据管理方式中的限制，并探索更加结构化的数据管理和分析方法。

---

# 2. 业务背景

## 2.1 在线语言教育业务流程

在线语言教育机构主要包含以下业务流程：

```text
市场获客

    ↓

客户咨询

    ↓

销售跟进

    ↓

试听课程 / 水平测试

    ↓

正式报名

    ↓

课程交付

    ↓

续费 / 结课
```

不同业务阶段会产生不同类型的数据：

| 业务阶段 | 产生的数据              |
| ---- | ------------------ |
| 市场获客 | 获客渠道、账号、帖子、曝光量、点击量 |
| 客户咨询 | 客户信息、咨询记录、跟进状态     |
| 试听课程 | 试听日期、试听教师、等级评估     |
| 正式报名 | 课程套餐、学生信息          |
| 课程交付 | 学生、教师、课程、排课信息      |

这些数据由不同团队产生，并服务于不同的业务目的。

用于记录：

* 上课日期；
* 上课时间；

## 运营数据

* 月度运营统计。

# 4. 初步业务问题

## 4.1 数据分散

当前业务数据根据不同业务流程产生，并分别存储在不同文件中。

一个学生的完整生命周期可能涉及：

```text
客户线索

↓

试听

↓

报名

↓

学生

↓

课程记录

↓

续费
```

不同阶段的数据需要通过人工方式进行关联。

这可能导致：

* 历史信息查询困难；
* 跨部门分析成本增加；
* 数据整理时间增加。

---

## 4.2 重复数据维护

相同的业务信息可能在多个文件中重复记录。

例如，学生信息可能同时存在于：

* 咨询记录；
* 试听记录；
* 报名记录；
* 学生汇总表；
* 课程记录。

这可能产生：

* 信息更新不同步；
* 多个版本同时存在；
* 人工核对成本增加。

---

## 4.3 缺乏统一的数据定义

部分业务字段缺少统一定义和标准。

例如，同一种课程类型可能被记录为：

```text
一对一

私教

单人私教

一对一私教
```

如果缺少统一的分类标准，将会影响：

* 数据查询；
* 指标统计；
* 数据看板分析；
* 不同时间周期之间的比较。

---

## 4.4 数据粒度混合

当前部分表格同时包含不同层级的数据。

例如：

运营数据中可能同时包含：

* 单条内容层级的数据；
* 账号层级的汇总数据。

学生管理数据中可能同时包含：

* 学生基本信息；
* 当前运营任务状态。

不同粒度的数据混合在同一张表中，会增加后续分析时重复计算或统计错误的风险。

---

## 4.5 人工统计依赖较高

部分业务指标目前仍然依赖人工整理。

例如：

* 试听转化率；
* 学生数量变化；
* 教师工作量；
* 班级开设情况；
* 月度运营统计。

随着业务规模扩大，人工统计所需要的时间和核对成本也会逐渐增加。

---

# 5. 业务影响

## 5.1 运营效率

当前的数据管理方式可能影响：

* 员工维护多个文件所需要的时间；
* 信息查询效率；
* 不同部门之间的信息交接；
* 新员工理解业务流程的速度。

---

## 5.2 数据一致性

当前数据管理方式可能出现：

* 不同文件中存在不同版本的信息；
* 数据更新无法及时同步；
* 统计结果需要额外进行人工确认。

---

## 5.3 数据分析能力

当前的数据结构限制了快速开展业务分析的能力。

例如，目前较难快速回答以下问题。

### 市场分析

* 哪些渠道能够带来更多有效客户？
* 哪些内容的表现更好？
* 不同市场渠道的获客效果是否存在明显差异？

### 销售分析

* 客户响应速度是否会影响最终转化？
* 不同销售人员的转化表现如何？
* 从咨询到试听、再到正式报名的转化情况如何？

### 教务运营分析

* 当前学生数量如何变化？
* 不同教师的工作量如何？
* 课程实际执行情况如何？
* 学生的续费情况如何？

# 6. 项目目标

## 6.1 理解当前数据环境

首先梳理当前业务的数据环境，包括：

* 数据来源；
* 数据维护部门；
* 数据用途；
* 数据之间的关系。

主要输出包括：

* 数据清单；
* 数据字典。

---

## 6.2 分析当前数据管理问题

重点分析：

* 数据分散问题；
* 重复维护问题；
* 字段标准问题；
* 数据关联问题；
* 数据粒度问题。

---

## 6.3 建立分析数据基础

根据实际业务流程，设计适合后续分析的数据模型。

主要业务实体包括：

| 业务实体 | 说明        |
| ---- | --------- |
| 客户线索 | 潜在客户信息    |
| 学生   | 学生基本信息    |
| 教师   | 教师基本信息    |
| 课程   | 课程类型及课程信息 |
| 报名   | 学生正式报名记录  |
| 课程记录 | 单次课程执行记录  |
| 续费   | 学生续费记录    |

这些数据实体将用于支持：

* 市场分析；
* 销售分析；
* 教务运营分析；
* 学生留存与续费分析。

# 10. 数据隐私说明

由于实际业务数据中包含敏感信息，例如：

* 学生个人信息；
* 家长联系方式；
* 教师信息；
* 内部运营记录。

因此，本项目不会公开真实业务数据。

公开仓库中的数据将采用以下方式处理：

* 使用模拟数据；
* 删除敏感字段；
* 对个人信息进行匿名化处理；
* 根据实际业务场景构造示例数据。

# 11. 项目定位

本项目希望展示一个较为完整的数据分析过程：

```text
业务问题

↓

业务流程理解

↓

数据审计

↓

数据建模

↓

数据查询与分析

↓

业务洞察
```

本项目的重点并不是开发一个新的业务系统，而是展示如何从真实业务问题出发，理解业务流程，整理现有数据结构，识别数据管理中的问题，并逐步建立能够支持运营分析的数据基础。

同时，本项目希望体现数据分析工作不仅包括最终的数据统计和可视化，还包括前期的业务理解、数据审计、数据标准化以及数据模型设计。
